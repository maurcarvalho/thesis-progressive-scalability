Apache Kafka &
A distributed event-streaming platform that provides high-throughput, fault-tolerant publish-subscribe messaging. In this work, Kafka serves as the event bus for inter-module communication, with per-module topics and consumer groups. \\

PostgreSQL &
An open-source object-relational database system. In the proposed architecture, each module owns an isolated schema within a shared PostgreSQL instance, enforced through Drizzle ORM's declarative \texttt{pgSchema()} per module. \\

Redis &
An in-memory key-value data store used for caching and request deduplication. Cache patterns include product catalog (TTL 5 min), order status (write-through, TTL 1 hr), and idempotency keys (TTL 24 hr). \\

Drizzle ORM &
A TypeScript ORM with declarative schema definitions. Each module defines its own \texttt{pgSchema()} for schema isolation within a shared PostgreSQL instance, enabling the Isolate level of progressive scalability. \\

\end{longtable}

Temporal &
A durable workflow execution engine for orchestrating long-running processes. In this work, Temporal manages the saga pattern via \texttt{orderFulfillmentWorkflow}, coordinating compensating actions (e.g., \texttt{releaseStock}, \texttt{refundPayment}) upon failure. \\

OpenTelemetry &
A vendor-neutral observability framework providing APIs and SDKs for collecting distributed traces, metrics, and logs. The proposed architecture scopes telemetry per module using module-specific tracers and metric prefixes, with W3C TraceContext propagation across Kafka headers. \\

Jaeger &
An open-source distributed tracing backend. Receives spans via the OpenTelemetry OTLP gRPC exporter and provides a web UI for trace visualization. Used in Guideline~6 (Observability Patterns) to inspect cross-module request flows. \\

Prometheus &
An open-source monitoring system with a time-series database. Scrapes metrics endpoints exposed by the application and provides PromQL for querying module-scoped metrics such as request rates, error rates, and latencies. \\

Grafana &
An open-source analytics and visualization platform. Connects to Prometheus as a data source and renders dashboards for module-level health, including per-module throughput divergence and error budgets. \\

Docker &
A container platform that packages applications and their dependencies into lightweight, portable images. The deployment strategy relies on Docker for both the monolith and extracted service artifacts. \\

Docker Compose &
A tool for defining multi-container applications. The reference architecture uses a single \texttt{docker-compose.yml} that provisions PostgreSQL, Kafka, Temporal, Jaeger, and Redis from day one. \\

Nx &
A monorepo build system that provides module-aware task scheduling~\cite{nx2024}. The \texttt{nx affected} command runs only the tests and builds impacted by a given change, enabling efficient CI pipelines without splitting the repository. \\

Kamal &
A deployment tool for containerized applications. Provides zero-downtime deployments with SSL termination for both monolith and extracted service configurations. \\

Kubernetes &
A container orchestration platform for automating deployment, scaling, and management. Referenced as the target runtime when horizontal scaling of extracted modules is required. \\

Anti-Corruption Layer &
A boundary pattern that translates between two different domain models, preventing one module's internal representation from leaking into another. Used in the Extract level to isolate the extracted service's API from the monolith's internal types. \\

CQRS &
Command Query Responsibility Segregation separates read and write operations into distinct models, allowing each to be optimized independently. \\

Event Sourcing &
A persistence pattern where state changes are stored as an immutable sequence of domain events rather than as mutable records. \\

Saga Pattern &
A distributed transaction pattern that coordinates a series of local transactions across services using compensating actions for rollback. Implemented via Temporal workflows in the reference architecture. \\

Strangler Fig &
An incremental migration pattern where new functionality is built alongside the existing system, gradually routing traffic to the new implementation until the old system can be retired~\cite{fowler2014}. \\

\end{longtable}
